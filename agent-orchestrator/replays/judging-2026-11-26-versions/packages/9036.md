### 9036-r1-j10  `frontend/src/renderer/lib/performance-telemetry.ts:312`

**Subtract post-layout script time from rendering, not from frame callbacks.**

`ResizeObserver` callbacks can run after `styleAndLayoutStart`. Line 312 classifies any script that starts at or after `tasksEnd` as callback time. Line 318 subtracts that total from the callback phase, which ends at `styleStart`. Line 319 counts the full `end - styleStart` as rendering. A script that starts after `styleStart` is therefore subtracted from the wrong phase, and its time remains in rendering.

For `startTime=100`, `duration=100`, `renderStart=110`, `styleAndLayoutStart=120`, and one 60 ms `user-callback` starting at 130 with no forced layout, the code reports:

- `unlisted` = 10 (line 317)
- `user-callback` = 60 (line 310)
- `frame-callbacks` = 0, because 120 − 110 − 60 = −50 is ignored by `add`
- `rendering` = 80 (line 319)

That totals 150 ms for a 100 ms frame. The 60 ms script is counted in both the script cause and rendering. The 10 ms interval from 110 to 120 is lost.

Subtract each script only from the phase it occupies. Scripts that start at or after `tasksEnd` and before `styleAndLayoutStart` should reduce `frame-callbacks`. Scripts that start at or after `styleAndLayoutStart` should reduce `rendering`. Keep the pre-layout callback interval as `frame-callbacks` after subtracting only the scripts in that interval. For the example, this gives 10 unlisted, 60 user-callback, 10 frame-callbacks, and 20 rendering, which totals 100 ms.

### 9036-r1-j13  `frontend/src/renderer/lib/performance-telemetry-properties.ts:55`

invokerName drops timer entry points, so long_frame_top_invoker skips them

The check at line 55 returns undefined when the character after the leading identifier is not `.`, `#` or `[`. As I remember Chrome's Long Animation Frame output, a timer callback's invoker is `TimerHandler:setTimeout` (or `TimerHandler:setInterval`). That has a `:` after `TimerHandler`, so it would be dropped. I did not verify this against Chrome.

If that is right, `user-callback` time from timers is counted in `long_frame_user_callback_ms` but never named. `long_frame_top_invoker` then reports the top entry point among the non-timer ones. A page dominated by timers would look like it was blocked by something else, which is the kind of question this PR is meant to answer.

Script-URL invokers are already skipped by type in `recordLongFrame` (`URL_INVOKER_TYPES`, performance-telemetry.ts:50 and :314). The colon restriction is therefore defence in depth. Could the check allow a bare `Identifier:identifier` form such as `TimerHandler:setTimeout` and still reject `https:`? Alternatively, `docs/telemetry.md` could say timers are not named.
