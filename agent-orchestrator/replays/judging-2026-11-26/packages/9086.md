### 9086-r1-i01  `backend/internal/devices/service.go:354`

**Keep the parked and owned records until `Shutdown` succeeds.**

For a running device, `retireParked` removes `s.parked` and `s.owned` and saves before it calls `Provider.Shutdown`. If the process exits during that call, the persisted state no longer records that AO owns the device or that it is parked. After a restart, nothing can retire the device, and it keeps running until the machine or the simulator is shut down manually. A `Shutdown` error does not cause this gap, because the error branch restores both records and saves them.

Keep both records while `releasing` blocks acquisition. Remove them only after `Shutdown` succeeds, then save. On failure, clear `releasing` and leave the records in place so the next pass retries. Keep the immediate removal for the not-running branch, which makes no provider call.

### 9086-r1-i02  `backend/internal/devices/service.go:882-883`

**Record ownership after a successful cold reopen.**

If a session leases an externally booted device, `owned` correctly remains false. If that device stops and the session reopens it, `Open` boots it again through `confirmReopen`. This commit still leaves `owned` false. When the session ends, `finishRelease` cannot park or retire the device AO just booted.

Carry the cold-boot result into this validated commit and record ownership before saving. Keep an already-running reopen unowned.

### 9086-r1-i03  `backend/internal/devices/service.go:365`

**Do not drop parked-device records when the device listing is incomplete.**

`retireParked` uses `Provider.List`. `List` can succeed while one platform's listing has failed. The failed platform's devices may be missing from the result. A running parked device that is missing from the result is treated as stopped. Lines 349-362 then delete its parked and ownership records. The `!running` branch at lines 364-366 skips shutdown. The device stays booted, and no later pass can retire it.

Retain the parked record when the device's platform listing failed. Check absence only against a platform-scoped listing, as `releaseIfGone` does. Keep the existing retry path for a failed list.

### 9086-r1-i04  `backend/internal/devices/service.go:251`

**Persist the parked association before releasing the lease.**

`endLeaseLocked` saves the lease removal before `finishRelease` records the parked session. If the daemon stops during `releaseControl` or `Shutdown`, the restored state keeps the device owned with no parked record. `retireParked` selects only parked devices, so it never shuts that device down. The device keeps running until something stops it outside AO.

Record the parked association in `endLeaseLocked`, in the same save that removes the lease.

### 9086-r1-i05  `backend/internal/devices/service.go:295`

A slow power-off pass holds up lease pruning in the reaper loop for up to 2 minutes

`reap` runs `pruneEnded` and then `retireParked` in one goroutine, so `retireParked` (bounded only by `retireTimeout`, 2 minutes, covering the session lookups, `List` and every sequential `Shutdown`) delays the next `pruneEnded` by up to that long. The ticker drops the missed ticks. `Open` and `Status` still call `pruneEnded` themselves, so leases are not stuck. But the idle-daemon guarantee in the comment at line 273 and in `device.md` ("within half a minute") no longer holds while a simulator is slow to shut down. Running `retireParked` in its own goroutine, or on its own ticker, would keep the two bounds independent. If you keep it sequential, loosen the wording.

### 9086-r1-i06  `backend/internal/devices/service.go:676`

**Do not drop device ownership based on a listing taken before an ownership change.**

`Open` lists devices before it takes `s.mu`. `forgetStoppedLocked` then uses that listing and the current idle state. A stale `Booted == false` can therefore clear ownership of a device that another session has since booted, committed, and warm-released. The device is then `running` with neither `owned` nor `parked` set. The reaper retires only parked devices, so the device stays on until the machine restarts. This is the leak this PR is meant to prevent.

Require that a stopped observation applies only if no ownership change occurred after the listing began. Record a device-state generation before the listing, or otherwise recheck the device's current running state under `s.mu` before deleting its ownership. Keep the cleanup when no intervening change occurred.

### 9086-r2-i01  `backend/internal/devices/service.go:385`

**Guard the retirement's off-listing with the boot generation.**

`retireParked` lists devices outside `s.mu`. It then deletes `parked` and `owned` entries for a device reported off, after checking only the session and idleness. If an `Open` boots the device during that window, the stale off listing can erase the new boot's records. The device keeps running and AO no longer tracks it, so it is never powered off.

Record `s.bootGen` before each platform listing. Skip the entry when `bootGen` has changed by the time the record is checked. The record stays parked for a later pass.
