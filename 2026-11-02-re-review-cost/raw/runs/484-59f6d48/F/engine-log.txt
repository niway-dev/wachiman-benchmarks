👮 **Wachiman** · 🟡🐛 **Consider · bug: Double-clicking a name to select it now toggles the row once instead of twice (confidence medium)**

The new guard covers a drag-select, but double-clicking a name (the other common way to select it for copying) goes the other way. In Chromium the word is selected on the second `mousedown`. So the first `click` (`detail === 1`) finds an empty selection and toggles the row. The second `click` finds the selected word and returns at line 216. Before this change the two toggles cancelled out and the row ended where it started. Now a double-click leaves the row unticked (or ticked again). Triple-click works the same way: one toggle, then two skipped clicks. The row dims, so the change is visible, but it's easy to miss after copying.

One option is to skip the guard when `event.detail > 1`. The repeat clicks would then toggle as before, and a double-click nets out to no change. Another is to toggle only on `event.detail === 1` and ignore the repeats, accepting the single toggle. The test only mocks a selection that already exists, so it doesn't cover either sequence.
