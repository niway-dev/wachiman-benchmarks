### 🟠🐛 **Fix · bug: Balanced, Light and YouTube copies lose their destination name, logo and picture size (confidence high)**

`apps/kaipu-record/src/renderer/src/features/prepare/components/master-copies-panel.tsx:192`

`destinationPresetOf` returns a preset only when the stored fingerprint is the bare "whole". Prepare does not store that: export-runner.ts:452-454 stores `encodeFingerprint(args.fingerprint, presetId)`, and export-presets.ts:177-188 appends a revision for balanced, light, youtube-1440 and youtube-4k. The sidecar value reaches the copy unchanged (library-vault.ts:157, 410-417; map-item.ts:25). So for those four presets line 192 returns null. The row then shows the file title (not "YouTube 1440p", "Slack · Discord · Email" or "GitHub · Jira · Linear"), the logo falls back to a film icon (CopyIcon, line 203-209), and the new picture size from `factsOf` (line 108) is dropped. Only vertical, square and maximum still match. The sibling checks do it right: export-reuse.ts:74 and prepare-page.tsx:226 compare against `encodeFingerprint(...)`. The function predates this PR, but the names, dimensions and the new test all depend on it. Fix: compare with `encodeFingerprint(WHOLE_RECORDING_FINGERPRINT, copy.export.preset)`, as export-reuse.ts:74 does.

### 🟠🧪 **Fix · tests: Fixtures use a fingerprint the app never writes, which hides the destination-name bug (confidence high)**

`apps/kaipu-record/src/renderer/src/features/prepare/components/master-copies-panel.test.tsx:59`

The fixtures use the bare `"whole"` fingerprint for youtube-1440 (line 59), light (line 63) and the default balanced copy (line 24). Production writes `whole#2560x1440-v1`, `whole#q33-24fps-kfi10` and `whole#q30-24fps-kfi10` (export-presets.ts:177-188). The test "names a destination copy by its destination" passes only because of that. Once the fix for master-copies-panel.tsx:192 lands, these fixtures stop matching and the test fails. Build the fixtures with `encodeFingerprint(WHOLE_RECORDING_FINGERPRINT, preset)` so they match what Prepare writes.
